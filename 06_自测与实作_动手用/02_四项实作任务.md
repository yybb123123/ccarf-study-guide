# CCAR-F 四项实践练习：个人训练清单（原创重述）

这些是依据官方考试指南的四类练习目标编排的个人任务，不是复制官方步骤。请打开官方 PDF 的 Hands-on Exercises 一节查看原始要求。

## Exercise 1 · Multi-Tool Agent with Escalation

目标：建立一条可解释、可中止、可人工接管的多工具请求处理流程。
- 定义三个只读工具和一个模拟写入工具。
- 写出权限边界、前置条件、结构化错误。
- 模拟超时、未授权、信息矛盾、请求升级。
- 证明工具调用循环按正确结束标记收尾。

## Exercise 2 · Claude Code Team Workflow

目标：通过 CLAUDE.md、Skills / Rules / Hooks、MCP 把团队操作变成可检查的流程。
- 编写项目规则、目录规则和安全注意事项。
- 加入一次自动化测试，并让 Agent 解释失败原因。
- 说明哪一部分由 Claude Code 执行、哪一部分由 CI / 系统权限执行。
- 验证没有把密钥放进公开仓库。

## Exercise 3 · Structured Data Extraction

目标：让模型提取非结构化证书字段并严格校验。
- 构造 20 份合成样本，包含缺失字段、格式错误和互相矛盾的日期。
- 定义 JSON Schema 和字段级错误处理。
- 区分可重试的格式错误与不可凭空推断的缺失事实。
- 汇总正确率、误报、漏报和转人工比例。

## Exercise 4 · Multi-Agent Research Pipeline

目标：使用 Coordinator 管理研究、核查、综合和引用。
- 将不同来源分给不同子任务，避免重复工作。
- 使用结构化消息传递结论、源网址和待验证项。
- 模拟一个 Subagent 失败并恢复。
- 最终报告必须区分“可靠来源事实”和“推测”。

## 每项任务的验收表

- [ ] 有输入样本和预期输出。
- [ ] 有可以复现的失败案例。
- [ ] 有源码、设置或工作流截图。
- [ ] 有验证方法，而不只是 AI 声称“已经完成”。
- [ ] 能用三分钟费曼方式解释“为什么这样设计”。
- [ ] 不含真实敏感客户数据。
