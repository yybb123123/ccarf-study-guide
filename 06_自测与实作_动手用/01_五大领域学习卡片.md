# CCAR-F 五大考试领域｜原创复习卡片

说明：本卡片帮助你准备讨论与动手练习；概念描述经过压缩，不能替代官方指南中每一条 Task Statement。请以 CCAR-F Exam Guide v1.1 为准。

## D1 · Agentic Architecture & Orchestration｜27%

- 说清 Workflow（固定流程）与 Agent（模型控制下一步行动）的区别。
- 理解工具调用循环：模型请求工具 → 执行工具 → 返回工具结果 → 再次调用模型；不要靠回复里出现“完成”两个字判定停止。
- 解释 coordinator / subagent 的职责和上下文隔离；传递必要事实与来源引用，不复制不相关的全部对话。
- 解释什么时候并行，什么时候必须串行，以及发生失败时如何中止或转人工。
- 区分 Prompt 提醒和程序性约束：关键权限、合规、费用控制应由代码或 Hooks 强制执行。

**自测**：如果用户请求“处理退款并修改账单”，怎样先校验客户身份、限制权限、并在失败时转人工？

## D2 · Tool Design & MCP Integration｜18%

- 把工具定义为有清晰名称、描述、输入 Schema、输出结构和边界条件的接口。
- 区分模型需要调用工具、工具执行失败、工具业务上返回无结果这三种不同状态。
- 熟悉 MCP 的架构及 Tools、Resources、Prompts 的角色；MCP 不会自动取代授权系统。
- 工具权限要遵循最小授权：只读查询不能拥有修改或退款权限。
- 辨别哪些事情只用普通 API 更简单，避免为了引入 MCP 而引入 MCP。

**自测**：两个查询工具都能找到用户信息时，怎样写描述才能让模型稳定选择正确工具？

## D3 · Claude Code Configuration & Workflows｜20%

- 学会按项目与目录设置 CLAUDE.md，并解释规则的作用范围。
- 区分 Skills（可复用指导）、Subagents（独立上下文任务）和 Hooks（执行点控制）。
- 在修改代码前先定位文件、明确验收标准、选择计划模式或直接执行。
- CI 中应运行非交互式的任务，明确退出码、测试结果与失败状态。
- 对 AI 自己产生的代码保持独立测试与审查，不能视为天然正确。

**自测**：如何让 Claude Code 自动审查 PR，但避免把模拟成功当作实际测试通过？

## D4 · Prompt Engineering & Structured Output｜20%

- 用明确标准和示例使结果可判断，不只说“尽量准确”。
- 理解 JSON 格式有效、Schema 有效和业务事实正确是三种不同检查。
- 设计字段级验证、错误回传、有限重试、转人工和日志。
- 评测要覆盖容易误判的边界条件，关心误报和漏报，不只评价回答是否流畅。
- 理解批量处理与实时处理的权衡：延迟、成本和业务时限。

**自测**：证书没有到期日期时，应返回 null、猜一个日期，还是一直重试？为什么？

## D5 · Context Management & Reliability｜15%

- 长上下文不是更多真相；选择必要信息并保留来源引用。
- 将多轮对话的事实、推断、待验证假设分开保存；旧的工具结果可能已失效。
- 在 subagent 间传递结构化结果、来源标识、未解决问题和错误状态。
- 明确置信度不足、来源矛盾或权限不足时的人工升级条件。
- 给系统设计可观测性、重试边界、错误恢复和独立验证。

**自测**：两份监管文件的培训要求冲突，Agent 应怎样组织证据并提示人工核查？

## 用 AfterSchool AI OS 做贯通案例

使用完全合成的 Staff Training 数据：员工 A 的 CPR 证书有效期不明确，员工 B 的培训记录缺学时。

1. 哪些判定由数据库和规则实现？
2. AI 负责哪些非结构化资料整理？
3. 哪些写入需要审批？
4. 如何记载证据来源、时间戳和错误？
5. 如何验证系统不会悄悄推测证书期限？

不要在学习笔记里输入任何真实孩子或员工的信息。
