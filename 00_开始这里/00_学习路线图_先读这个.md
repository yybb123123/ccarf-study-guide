# 学习路线图 · CCAR-F 两周攻坚

**适用对象：** 在职、每天能挤出 1–2 小时、目标是「理解+能讲出来」而不是背题。

**总投入：** 约 20–25 小时。时间不够时，砍第 5 阶段，别砍第 3 阶段。

---

## 阶段 0 · 建立地图（约 2 小时，一次做完）

1. 读 `01_官方考纲_必读_最优先/00_CCAR-F_Exam_Guide_v1.1_官方42页.pdf` 的目录 + 五大领域章节标题，
   **用笔记列出每个领域下的 Task Statement 编号**（这是后面所有学习的抓手）。
2. 读 `00_开始这里/01_考试资料索引_先读这个.md`，确认权重：D1 27% / D3 20% / D4 20% / D2 18% / D5 15%。
3. 搭好 NotebookLM：上传考纲 PDF + `00_开始这里` 里的全部文本，粘贴费曼提示词。

## 阶段 1 · 打地基（第 1–2 天，5 篇低难度）

按 `02_低难度_必读_打地基` 里的编号顺序读，读完每篇用 3 句话写下「它解决什么问题」。

| 天 | 读什么 | 关键问题 |
| --- | --- | --- |
| D1 | 01 Building Effective Agents + 02 Agent SDK Overview | Workflow 和 Agent 的分界线在哪？ |
| D2 | 03 MCP 官方介绍 + 04 Memory/CLAUDE.md + 05 Prompting 指南 | 规则该写在 CLAUDE.md 还是代码里？ |

## 阶段 2 · 主攻（第 3–11 天，占全部投入的 70%）

`03_中高难度_必读_主攻` 里 10 份文档，**按编号顺序**，一天一篇，厚文档拆分：

| 天 | 编号与文件 | 领域权重 | 读完要能做到 |
| --- | --- | --- | --- |
| D3 | 01 Multi-agent Research System | D1 · 27% | 画出 coordinator→subagent→汇总的消息流 |
| D4 | 02 Claude Code Subagents | D1 · 27% | 说清上下文隔离传什么、不传什么 |
| D5 | 03 Claude Code Skills | D3 · 20% | 区分 Skills / Rules / Hooks 三者 |
| D6–D7 | 04 Claude Code Hooks（167 页，拆 2 天） | D3 · 20% | 说出每个 hook 的执行点与失败后果 |
| D8 | 05 Structured Outputs | D4 · 20% | 区分「JSON 合法」与「业务正确」 |
| D9 | 06 Develop Evaluations + 07 Message Batches | D4 · 20% | 设计一个能抓误报的评测集 |
| D10 | 08 Tool Use Overview | D2 · 18% | 三种「没结果」的区别 |
| D11 | 09 Contextual Retrieval + 10 Demystifying Evals | D5 · 15% | 说清来源归属与人工升级条件 |

## 阶段 3 · 动手（贯穿阶段 2，每周末 2–3 小时）

`06_自测与实作_动手用/02_四项实作任务.md` 里的四项练习，和领域正好对应：

- Exercise 1 Multi-Tool Agent ↔ D1+D2　→ 配 `03` 的 01/02/08
- Exercise 2 Claude Code Workflow ↔ D3　→ 配 `03` 的 03/04
- Exercise 3 Structured Extraction ↔ D4　→ 配 `03` 的 05/06
- Exercise 4 Multi-Agent Research ↔ D5　→ 配 `03` 的 09/10

每项都要留下**可复现的失败案例**，这是验收表里最容易被跳过、也最能拉开差距的一条。

## 阶段 4 · 查漏与考试信息（考前 1–2 天，1 小时）

- `05_低优先_选读_课程与认证信息/02_官方认证FAQ.pdf`：考试形式、时长、重考规则
- `05_.../01_CCAR-F_官方认证主页.pdf`：报名与证书
- `06_自测与实作_动手用/01_五大领域学习卡片.md`：五个领域的自测题各过一遍，答不上来的回去翻 `03`

## 阶段 5 · 选读（时间富余才做）

`04_高难度_选读_深水区` 全是工程细节（MCP Python SDK、Bedrock、Vertex、API 深水）。
**考纲不直接考，投入产出比低**，只有在你想真正落地实现时才读。

---

## 每天 60 分钟的固定节奏（可直接照做）

1. **10 分钟**　回看昨天的自测题，答不出的标记出来。
2. **35 分钟**　读当天文档，边读边写「如果考我，会怎么问」。
3. **10 分钟**　用费曼法讲给自己听：合上文档，口述这一节的核心机制。
4. **5 分钟**　把讲不顺的地方记成一句话问题，第二天先解决它。

---

## 三个提醒

- **别从 Hooks 开始。** 它最厚最硬，先读会劝退；等你熟悉了配置语境再啃。
- **05 文件夹不是教材。** 那是课程落地页，正文要登录，别指望它替代官方文档。
- **考纲永远是最高优先级。** 任何资料里出现考纲没写的功能，都不要当成必考。
