    Practice & Exams

    五个领域的自测题与四项动手实作。答案在官方文档里，不在这里。

    自测题

    先自己答，再展开对照要点

    D1如果用户要求「处理退款并修改账单」，怎样先校验身份、限制权限、失败时转人工？
    • 说清 Workflow（固定流程）与 Agent（模型决定下一步）的区别
    • 工具调用循环：模型请求 → 执行 → 回传 → 再调用；不靠「完成」二字判断结束
    • coordinator / subagent 的职责与上下文隔离，只传必要事实与来源
    • 何时并行、何时必须串行，失败时如何中止或转人工
    • 关键权限、合规、费用控制应由代码或 Hooks 强制执行，而非提示词
    D2两个查询工具都能找到用户信息时，描述怎么写才能让模型稳定选对？
    • 工具 = 清晰名称 + 描述 + 输入 Schema + 输出结构 + 边界条件
    • 区分三种状态：模型要调工具 / 工具执行失败 / 业务上查无结果
    • MCP 的 Tools、Resources、Prompts 三角色；它不自动取代授权系统
    • 最小授权：只读查询不能拥有退款或写入权限
    • 能用普通 API 解决就别引入 MCP
    D3如何让 Claude Code 自动审查 PR，但不把「模拟成功」当成测试通过？
    • CLAUDE.md 的项目级与目录级规则，及其作用范围
    • Skills（可复用指导）/ Subagents（独立上下文）/ Hooks（执行点控制）三者分工
    • 改代码前先定位文件、明确验收标准，再选计划模式或直接执行
    • CI 里跑非交互任务，明确退出码与失败状态
    • AI 生成的代码必须独立测试与审查
    D4证书没有到期日期时，应返回 null、猜一个日期，还是一直重试？为什么？
    • 用明确标准和示例让结果可判定，别说「尽量准确」
    • JSON 格式合法、Schema 合法、业务事实正确，是三种不同检查
    • 字段级校验、错误回传、有限重试、转人工、日志
    • 评测要覆盖易误判的边界，关心误报与漏报
    • 批处理与实时的取舍：延迟、成本、业务时限
    D5两份监管文件的培训要求冲突时，Agent 应怎样组织证据并提示人工核查？
    • 长上下文不等于更多真相，选必要信息并保留来源引用
    • 事实、推断、待验证假设分开保存；旧工具结果可能失效
    • 子代理之间传结构化结果、来源标识、未决问题与错误状态
    • 置信度不足、来源矛盾、权限不足时的人工升级条件
    • 可观测性、重试边界、错误恢复、独立验证

    四项实作

    考纲要求动手

    Exercise 1D1 + D2

    Multi-Tool Agent with Escalation

    • 定义 3 个只读工具 + 1 个模拟写入工具
    • 写出权限边界、前置条件、结构化错误
    • 模拟超时、未授权、信息矛盾、请求升级
    • 证明工具循环按正确结束标记收尾
    Exercise 2D3

    Claude Code Team Workflow

    • 编写项目规则、目录规则与安全注意事项
    • 加入一次自动化测试，让 Agent 解释失败原因
    • 说明哪部分由 Claude Code 执行、哪部分由 CI/系统权限执行
    • 验证没有把密钥放进公开仓库
    Exercise 3D4

    Structured Data Extraction

    • 构造 20 份合成样本：缺字段、格式错、日期矛盾
    • 定义 JSON Schema 与字段级错误处理
    • 区分可重试的格式错误与不可凭空推断的缺失事实
    • 汇总正确率、误报、漏报、转人工比例
    Exercise 4D1 + D5

    Multi-Agent Research Pipeline

    • 把不同来源分给不同子任务，避免重复工作
    • 用结构化消息传结论、源网址、待验证项
    • 模拟一个子代理失败并恢复
    • 最终报告区分「可靠来源事实」与「推测」
