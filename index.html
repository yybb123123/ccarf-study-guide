五大领域 · 要能解释什么

每个领域后面是它的自测题，答不上来说明还没读完。

D1

Agent 架构与编排

Agentic Architecture & Orchestration

27%
  • 说清 Workflow（固定流程）与 Agent（模型决定下一步）的区别
  • 工具调用循环：模型请求 → 执行 → 回传 → 再调用；不靠「完成」二字判断结束
  • coordinator / subagent 的职责与上下文隔离，只传必要事实与来源
  • 何时并行、何时必须串行，失败时如何中止或转人工
  • 关键权限、合规、费用控制应由代码或 Hooks 强制执行，而非提示词

自测如果用户要求「处理退款并修改账单」，怎样先校验身份、限制权限、失败时转人工？

D2

工具设计与 MCP

Tool Design & MCP Integration

18%
  • 工具 = 清晰名称 + 描述 + 输入 Schema + 输出结构 + 边界条件
  • 区分三种状态：模型要调工具 / 工具执行失败 / 业务上查无结果
  • MCP 的 Tools、Resources、Prompts 三角色；它不自动取代授权系统
  • 最小授权：只读查询不能拥有退款或写入权限
  • 能用普通 API 解决就别引入 MCP

自测两个查询工具都能找到用户信息时，描述怎么写才能让模型稳定选对？

D3

Claude Code 配置与工作流

Claude Code Configuration & Workflows

20%
  • CLAUDE.md 的项目级与目录级规则，及其作用范围
  • Skills（可复用指导）/ Subagents（独立上下文）/ Hooks（执行点控制）三者分工
  • 改代码前先定位文件、明确验收标准，再选计划模式或直接执行
  • CI 里跑非交互任务，明确退出码与失败状态
  • AI 生成的代码必须独立测试与审查

自测如何让 Claude Code 自动审查 PR，但不把「模拟成功」当成测试通过？

D4

提示词与结构化输出

Prompt Engineering & Structured Output

20%
  • 用明确标准和示例让结果可判定，别说「尽量准确」
  • JSON 格式合法、Schema 合法、业务事实正确，是三种不同检查
  • 字段级校验、错误回传、有限重试、转人工、日志
  • 评测要覆盖易误判的边界，关心误报与漏报
  • 批处理与实时的取舍：延迟、成本、业务时限

自测证书没有到期日期时，应返回 null、猜一个日期，还是一直重试？为什么？

D5

上下文管理与可靠性

Context Management & Reliability

15%
  • 长上下文不等于更多真相，选必要信息并保留来源引用
  • 事实、推断、待验证假设分开保存；旧工具结果可能失效
  • 子代理之间传结构化结果、来源标识、未决问题与错误状态
  • 置信度不足、来源矛盾、权限不足时的人工升级条件
  • 可观测性、重试边界、错误恢复、独立验证

自测两份监管文件的培训要求冲突时，Agent 应怎样组织证据并提示人工核查？

    验收表 · 六条全过才算做完

    五道自测题

    先自己答，再展开对照要点。答不上来的，就是明天要补的地方。

    D1 如果用户要求「处理退款并修改账单」，怎样先校验身份、限制权限、失败时转人工？

    这个领域要能覆盖：

    • 说清 Workflow（固定流程）与 Agent（模型决定下一步）的区别
    • 工具调用循环：模型请求 → 执行 → 回传 → 再调用；不靠「完成」二字判断结束
    • coordinator / subagent 的职责与上下文隔离，只传必要事实与来源
    • 何时并行、何时必须串行，失败时如何中止或转人工
    • 关键权限、合规、费用控制应由代码或 Hooks 强制执行，而非提示词
    D2 两个查询工具都能找到用户信息时，描述怎么写才能让模型稳定选对？

    这个领域要能覆盖：

    • 工具 = 清晰名称 + 描述 + 输入 Schema + 输出结构 + 边界条件
    • 区分三种状态：模型要调工具 / 工具执行失败 / 业务上查无结果
    • MCP 的 Tools、Resources、Prompts 三角色；它不自动取代授权系统
    • 最小授权：只读查询不能拥有退款或写入权限
    • 能用普通 API 解决就别引入 MCP
    D3 如何让 Claude Code 自动审查 PR，但不把「模拟成功」当成测试通过？

    这个领域要能覆盖：

    • CLAUDE.md 的项目级与目录级规则，及其作用范围
    • Skills（可复用指导）/ Subagents（独立上下文）/ Hooks（执行点控制）三者分工
    • 改代码前先定位文件、明确验收标准，再选计划模式或直接执行
    • CI 里跑非交互任务，明确退出码与失败状态
    • AI 生成的代码必须独立测试与审查
    D4 证书没有到期日期时，应返回 null、猜一个日期，还是一直重试？为什么？

    这个领域要能覆盖：

    • 用明确标准和示例让结果可判定，别说「尽量准确」
    • JSON 格式合法、Schema 合法、业务事实正确，是三种不同检查
    • 字段级校验、错误回传、有限重试、转人工、日志
    • 评测要覆盖易误判的边界，关心误报与漏报
    • 批处理与实时的取舍：延迟、成本、业务时限
    D5 两份监管文件的培训要求冲突时，Agent 应怎样组织证据并提示人工核查？

    这个领域要能覆盖：

    • 长上下文不等于更多真相，选必要信息并保留来源引用
    • 事实、推断、待验证假设分开保存；旧工具结果可能失效
    • 子代理之间传结构化结果、来源标识、未决问题与错误状态
    • 置信度不足、来源矛盾、权限不足时的人工升级条件
    • 可观测性、重试边界、错误恢复、独立验证
